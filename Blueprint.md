4. CORE ARCHITECTURE: CLIENT-FIRST, SERVER-MINIMAL

This is the most important technical requirement.

The vast majority of ordinary tools should execute entirely in the user's browser.

Architecture targets

- At least 80–90% of ordinary tool operations should require no application-server processing.
- Static assets should be CDN-delivered.
- Large files should be processed locally wherever feasible.
- No central database should be necessary for basic tool usage.
- Avoid unnecessary API calls.
- Avoid server-side processing where browser APIs can perform the task.

These are engineering targets, not guaranteed measurements. Validate them against the actual product catalogue.

Technologies to evaluate

Frontend:

- Next.js.
- React.
- TypeScript.
- Tailwind CSS.

Execution:

- Native browser APIs.
- Web Workers.
- WebAssembly.
- Web Crypto API.
- IndexedDB.
- LocalStorage where appropriate.
- Canvas API.
- File System Access API where supported.
- WebGPU where useful.

Potential libraries:

- PDF.js.
- pdf-lib.
- jsPDF.
- Squoosh codecs.
- Browser-compatible image compression libraries.
- QRCode libraries.
- WASM compression libraries.

Evaluate maintenance, bundle size, browser compatibility, security and licensing before selecting dependencies.

Hosting

Evaluate:

- Cloudflare Pages.
- Cloudflare CDN.
- Cloudflare Workers.
- Cloudflare R2.
- Static asset caching.
- Alternative static hosting providers.

Workers or backend services should only be used where genuinely necessary.

Do not introduce PostgreSQL, Supabase, Redis or another permanent database without a documented requirement.
